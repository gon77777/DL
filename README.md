# きゅうりDL

yt-dlp を内蔵した Android 用メディアダウンローダー。黒と金の UI、絵文字なし。

## 機能

- 多数の動画サイトに対応 (yt-dlp の対応サイト全般)
- X (Twitter) などのアカウントの画像・動画を一括ダウンロード (gallery-dl)。画像のみ / 動画のみ / 両方を選べ、`images` と `videos` に分けて保存
- 再生リストの一括ダウンロード (番号付きフォルダへ保存)
- 音声のみの保存 (MP3 / M4A / OPUS / FLAC、ビットレート指定 192K / 128K)
- yt-dlp 本体をボタン一つで最新版へ更新 (STABLE / NIGHTLY を選択可)
- yt-dlp の自動更新: アプリ起動時に更新 (設定で切り替え、初期値はOFF)
- バックグラウンドでもダウンロード継続 (フォアグラウンドサービス + 通知から操作可能)
- ブラウザなど他アプリの「共有」から URL を直接受け取り
- 完了したファイルを端末の標準プレーヤーで再生、または他アプリへ共有
- Wi-Fi接続時のみ実行 (設定で切り替え、初期値はON)
- 音声保存時に、動画のサムネイルをアルバムアートとして埋め込み
- 保存先: 標準は端末の `Download/KyuuriDL`。設定で好きなフォルダに変更可能

### 画質・形式の細かい指定

- 画質: BEST / 2160P / 1440P / 1080P / 720P / 480P / 360P (指定した画質が無い動画は近い画質を自動選択)
- 保存形式 (コンテナ): MP4 / MKV / WEBM
- 映像コーデックの優先: 自動 / H.264 / VP9 / AV1
  - 自動の場合、MP4 は H.264、WEBM は VP9 を優先。MKV は最も高画質な組み合わせ
- 選んだ内容は次回起動時にも引き継がれます

### ダウンロード前のプレビュー

- 「プレビュー」でタイトル、サムネイル、投稿者、長さ、選べる画質の一覧を確認
- 再生リストは中身の一覧を表示し、保存する動画だけをチェックして選択可能

### 同時ダウンロード数

- 1〜5 件から選択 (初期値 2)。ダウンロード中に変更しても次の項目から反映

### 一時停止と再開

- 項目ごと、または「すべて一時停止」で停止。再開すると途中のデータから続きを取得
- 通知の「一時停止」ボタンからも操作可能
- 失敗・停止した項目は「再試行」で最初からやり直し

### yt-dlp の自動更新

- 設定の「yt-dlpの自動更新」をONにすると、アプリを起動するたびに、選択中のチャンネル (STABLE / NIGHTLY) の最新版へ更新します (初期値はOFF)
- 結果は上部の YT-DLP ENGINE カードに表示されます
- 「Wi-Fi接続時のみ実行」がONでモバイル回線のときは、通信量を使わないよう自動更新を見送ります
- 設定をONにした直後は更新しません。次回の起動から動きます

### 保存先の変更

- 標準の保存先は `Download/KyuuriDL` です。設定の「保存先」から「フォルダを選ぶ」で、好きなフォルダ (内部ストレージ・SDカード) へ変更できます
- 変更は、これ以降のダウンロードから反映されます。すでに保存したファイルは移動しません
- 再生リストは、選んだフォルダの中に再生リスト名のフォルダを作って保存します
- Android の制限により、端末の最上位と「ダウンロード」フォルダ自体は選べません。専用のフォルダを作ってから選んでください
- 選んだフォルダが削除された、または権限が失われた場合は、標準の保存先へ自動で退避し、その旨を表示します
- 「標準に戻す」でいつでも `Download/KyuuriDL` に戻せます

### 再生と共有

- 完了した項目の「再生」で、端末の標準プレーヤー (音楽・動画アプリ) で開きます
- 「共有」で、他アプリ (メッセージ、クラウド、メモリーカード系アプリなど) へ送れます
- 再生リストなど複数ファイルの項目は、一覧から選んで再生、または「すべて共有」ができます
- Download フォルダからファイルを移動・削除した場合は「ファイルが見つかりません」と表示されます

### Wi-Fi接続時のみ実行

- 設定の「Wi-Fi接続時のみ実行」で切り替え (初期値はON)。Wi-Fi・有線LAN・Wi-Fi上のVPNを「Wi-Fi」とみなします
- ONのままモバイル回線になると、実行中の項目は自動で一時停止し「Wi-Fi待ち」になります。変換中の項目だけはそのまま完了します
- Wi-Fiに接続すると、「Wi-Fi待ち」の項目が自動で続きから再開します。設定をOFFにしても再開します
- モバイル回線中に追加・再試行した項目も、Wi-Fiに接続するまで待機します
- 利用者が手動で一時停止した項目は、自動では再開しません
- 対象はダウンロードの実行です。プレビューの取得と yt-dlp 本体の更新は制限しません

### サムネイルとメタデータの埋め込み

- 音声のみの保存 (MP3 / M4A / OPUS / FLAC) で、動画のサムネイルをアルバムアートとして埋め込みます
- タイトル・アーティスト等のタグも同時に書き込みます
- サムネイルは、どのプレーヤーでも読める JPEG に変換して埋め込みます
- サムネイルが無い動画では、アートなしで保存されます

### 高速モード (分割ダウンロード)

- 1つの動画を複数の接続に分けて同時に取得し、最後に1本にまとめます (設定の「高速モード」。初期値はOFF)
- 同時接続数は 4〜16 本をスライダーで選べます。まずは 8 本がおすすめです
- 回線そのものの速度は超えられません。サイトが「1接続あたりの速度」を制限している場合に効果があります
- 接続を増やしすぎると、サイトに制限されることがあります (速度の低下、途中停止、HTTP 403 / 429 での失敗、しばらくダウンロードできなくなる)。その場合は本数を下げるか OFF にしてください
- CPU・電池・通信量の使用も増えます

### キューの保存

- 待機中・一時停止中・完了済みの項目は端末に保存され、アプリが強制終了されても失われません
- 次にアプリを開くと、実行中だった項目は待機中に戻り、取得済みの部分 (.part) から続きを再開します

### 取得済みの分をスキップ

- 再生リストとアカウント一括を取り直すとき、取得済みの分を飛ばして新着だけ保存します (単体の動画は毎回取得します)
- 取得済みの記録は取得元のURLごとに端末内へ保存され、設定した日数 (7 / 30 / 90日 / 無期限) のあいだ使われなかった記録は、アプリ起動時に自動で消えます。使うたびに期限は延びます (無期限なら自動では消えません)
- 新しい分が無かった場合は、失敗ではなく「新しい分はありませんでした」で完了します
- 設定でオフにできます。「記録をすべて消去」で、いつでも全件を取り直せます

### アカウント一括ダウンロード (gallery-dl)

X (Twitter) や Pixiv などのアカウントの URL を入れるだけで、そのアカウントの画像・動画をまとめて保存します。

- 入力欄の上の「アカウント一括」を選び、アカウントの URL を入力して「アカウントを一括ダウンロード」
  - X は `https://x.com/ユーザー名` (twitter.com の URL でも可)。プロフィールは「メディア」タブ (`/media`) として取得します
  - 複数のアカウントは改行で区切って入力できます
- 取得する種類を切り替え: 「画像と動画」/「画像のみ」/「動画のみ」 (選んだ内容は次回も引き継ぎます)
- 保存先の中に `アカウント名` のフォルダを作り、その中を `images` と `videos` に分けて保存します
  - 例: `Download/KyuuriDL/x_ユーザー名/images/…` と `Download/KyuuriDL/x_ユーザー名/videos/…`
  - 保存先を「フォルダを選ぶ」で変えている場合は、そのフォルダの中に同じ構成で作ります
- 進行中は保存できた枚数・本数が表示されます。一時停止・再開・停止・Wi-Fi 限定は、通常のダウンロードと同じように使えます
  - 再開すると、保存済みのファイルは飛ばして続きから取得します
  - 保存は 1 ファイルずつその場で行うため、大きなアカウントでも端末の空き容量を二重には使いません
- 「ログイン」: アプリ内のブラウザで対象サイトにログインします。パスワードはアプリでは扱わず、ログイン情報 (Cookie) だけをこの端末のアプリ専用領域に保存します。「ログアウト」でいつでも削除できます
  - **X はログインが必須です** (ログインしていると「アカウントを一括ダウンロード」を押したときに案内が出ます)
  - X の仕様により、ログインしたアカウントで見られる範囲が対象で、古い投稿まで取得できない場合があります。非公開アカウントは、そのアカウントをフォローしているアカウントでログインしたときだけ取得できます
  - **Pixiv もログインが必須です。** gallery-dl の Pixiv は Cookie ではなく「リフレッシュトークン」(OAuth) で認証するためで、「ログイン」を押すと Pixiv の公式ログインが開き、ログインすると自動でトークンを保存して閉じます
  - ログイン画面が進まないときは、画面右上の「PC表示」に切り替えて開き直すと通ることがあります。画面下部の案内欄に、通信エラーなどの手がかりが表示されます
  - X は、認証用の Cookie を検出すると、「完了」を押さなくても自動で保存して閉じます
  - それでも動かないときの代わりの方法が「手動で入力」です。X は、パソコンのブラウザで x.com にログインし、F12 → 「アプリケーション (Application)」タブ → 「Cookie」→ `https://x.com` の `auth_token` と `ct0` の値をコピーして、それぞれの欄へ貼り付けます (「コンソール」では見えません)
  - Pixiv は、「ログイン」ボタンだけで自動的にトークンが登録されます。パソコン操作は不要です
  - X のログイン画面は、WebView だと分かる印 (User-Agent の `wv` / `Version/4.0`、`X-Requested-With`) を外して開きます
  - X 以外のサイトは、gallery-dl が対応しているサイトなら URL を入れるだけで取得できます (必要なサイトだけログインしてください)

#### yt-dlp の更新の安全装置

- 更新の前に、動いている yt-dlp を控えておきます。更新後に実際に起動して確かめ、動かなければ元の版へ自動で戻します
- 最新版が端末の Python では動かない場合 (PyPI の「必要な Python のバージョン」で判定) は、動く最新版を GitHub のリリースから入れます。この場合 NIGHTLY は選べません
- 端末の Python の版や PyPI の情報を取得できないときは、従来どおり選択中のチャンネルの最新版へ更新します

#### gallery-dl の更新

yt-dlp と同じく、手動・自動の両方で最新版に更新できます。X などは仕様変更で取得できなくなることがあるため、うまく取得できなくなったら更新してください。

- 手動: 「GALLERY-DL ENGINE」カードの「最新版に更新」
- 自動: 設定の「gallery-dlの自動更新」をONにすると、アプリを起動するたびに最新版へ更新します (初期値はOFF)。「Wi-Fi接続時のみ実行」がONでモバイル回線のときは見送ります
- 更新は PyPI の情報にある「必要な Python のバージョン」を見て、端末の Python で動く最新版を選びます。最新版が動かない場合は、動く最新版に更新し、その旨を表示します
- 入れ替える前に、端末の Python で起動できることを確かめます。動かない版だった場合は、いま動いている版をそのまま残します
- アカウント一括のダウンロード中は更新できません
- gallery-dl は、アプリに同梱した版 (初回に端末内へ展開) から始まります。アプリ自体を更新すると、同梱の版に戻ります

内部では [youtubedl-android](https://github.com/yausername/youtubedl-android) (yt-dlp + Python + FFmpeg を同梱) と、アカウント一括用の [gallery-dl](https://github.com/mikf/gallery-dl) を使用しています。

## APK の作り方 (GitHub Actions)

1. GitHub で新しいリポジトリを作成し、このフォルダの中身をプッシュします。

   ```
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```

2. プッシュすると `Build APK` ワークフローが自動で動きます。リポジトリの Actions タブで確認してください。
3. 完了後、実行結果ページの Artifacts から `AurumDL-apk` をダウンロードします。
4. 中の APK を端末へ入れてインストールします。
   - 迷ったら `app-universal-release.apk` (全端末対応、サイズ大)
   - 最近のスマートフォンなら `app-arm64-v8a-release.apk` (小さい)

`v1.0.0` のようなタグをプッシュすると、同じ APK が GitHub Releases にも公開されます。

### ローカルでビルドする場合

Android SDK と JDK 17 を用意し、Gradle 8.9 で実行します。

```
gradle assembleRelease
```

出力: `app/build/outputs/apk/release/`

## 注意

- APK は debug 鍵で署名されます。自分用途には問題ありませんが、ストア配布をする場合は専用の署名鍵を設定してください。
- 初回起動時は yt-dlp の展開に数秒かかります。サイト側の仕様変更で取得に失敗したときは、アプリ内の「最新版に更新」(必要なら NIGHTLY) を試してください。
- Android 10 (API 29) 以上が必要です。
- 著作権や各サイトの利用規約に従い、権利のあるコンテンツにのみ使用してください。
